Red Team Report: My File Server 1

Ejercicio integral de pentesting, explotación de servicios y escalada de privilegios a nivel de kernel[cite: 22, 23].

Nivel de Riesgo: Crítico | Objetivo IP: 10.0.2.4 (CentOS 7)

Detalles del Reporte Técnico

Resumen Ejecutivo (Executive Summary)

Durante la ejecución del ejercicio de Pentesting sobre el servidor objetivo, se logró comprometer la infraestructura en su totalidad, escalando privilegios hasta obtener acceso administrativo absoluto (root). El riesgo se clasifica como crítico debido a una mala configuración en el servidor web que exponía credenciales en texto claro, combinada con la vulnerabilidad crítica de kernel conocida como DirtyCow (CVE-2016-5195).

Alcance (Scope) y Metodología

La evaluación se delimitó a la máquina virtual "My File Server: 1" (CentOS 7) operando en la IP 10.0.2.4 bajo un entorno aislado en Red NAT. Se evaluaron los servicios FTP, SSH, HTTP y SMB/Samba. Como marco de trabajo se aplicó el estándar PTES (Penetration Testing Execution Standard)[cite: 24].

Fases de Reconocimiento y Enumeración

  • Descubrimiento: Uso de netdiscover para ubicar la IP 10.0.2.4 en la red local[cite: 25].
  • Escaneo de puertos: nmap -p- -sV reveló servicios activos como vsftpd 3.0.2, OpenSSH 7.4, Apache 2.4.6 y Samba[cite: 25].
  • Auditoría Web & SMB: Nikto descubrió el archivo expuesto /readme.txt[cite: 26], mientras que smbmap identificó el recurso compartido smbdata con permisos de lectura/escritura (sesión nula)[cite: 26].

Explotación y Acceso Inicial

A partir de las credenciales obtenidas, se generó un par de llaves SSH (ssh-keygen)[cite: 27]. Mediante una sesión FTP autenticada con el usuario smbuser, se creó el directorio .ssh y se subió la llave pública como authorized_keys[cite: 27]. Esto permitió establecer una conexión SSH persistente y segura sin requerir contraseña[cite: 27].

Escalada de Privilegios (DirtyCow / CVE-2016-5195)

Al auditar la versión del kernel (uname -a), se detectó el entorno Linux 3.10.0-229 vulnerable a DirtyCow[cite: 28]. Se descargó el exploit de código fuente (40616.c) mediante un servidor HTTP temporal en Python, se compiló con gcc -pthread y al ejecutarlo se sobrescribió el archivo de contraseñas, otorgando una shell interactiva como usuario root y extrayendo la bandera final en /root/proof.txt[cite: 28, 29].

Análisis de Impacto y Recomendaciones

El impacto afecta gravemente la Confidencialidad, Integridad y Disponibilidad (Modelo CIA)[cite: 29]. Se recomienda aplicar un parche urgente al kernel para mitigar CVE-2016-5195, eliminar archivos sensibles expuestos en el servidor web, restringir permisos en los recursos SMB y realizar un endurecimiento (hardening) general de los servicios[cite: 29].
