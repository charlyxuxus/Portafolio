Laboratorio de Path Traversal

File Path Traversal, Validation of File Extension with Null Byte Bypass

Nivel: Practitioner[cite: 7] | Tipo de explotación: Path Traversal / Bypass de Extensión[cite: 7]

Detalles del Reporte

Objetivo del laboratorio

El objetivo de este laboratorio es explotar una vulnerabilidad de path traversal en la funcionalidad de visualización de imágenes de productos de una aplicación web, la cual exige de manera estricta que los archivos solicitados terminen con una extensión específica (como .png)[cite: 7]. Para resolverlo, se debe evadir esta validación lógica utilizando un byte nulo (%00) que permita burlar el filtro del backend y lograr extraer con éxito el contenido del archivo crítico del sistema operativo, /etc/passwd[cite: 7].

Explicación técnica de la vulnerabilidad

La vulnerabilidad se origina en una deficiencia en la validación de las entradas y en la disparidad en cómo se procesan las cadenas de texto entre la lógica de la aplicación web y el sistema operativo subyacente[cite: 7]. La aplicación implementa una validación basada en la extensión del archivo, bloqueando cualquier solicitud que no finalice con un tipo permitido[cite: 7]. Sin embargo, si el backend utiliza funciones de bajo nivel que interpretan un byte nulo (%00) como fin de cadena (null terminator), la validación de la extensión se trunca a nivel de sistema operativo, permitiendo la lectura de archivos arbitrarios[cite: 7].

Procedimiento paso a paso

  1. El proceso inicia abriendo la aplicación Burp Suite y utilizando su navegador integrado para evitar conflictos con certificados de seguridad[cite: 7].
  2. En la sección Proxy > Intercept, se verifica que la función de intercepción esté activada (Intercept is on) para capturar las peticiones HTTP de las imágenes[cite: 7].
  3. Haciendo clic derecho sobre la petición capturada en el historial, se selecciona la opción Send to Repeater para facilitar el envío manual y controlado de solicitudes[cite: 7].
  4. Dentro del Repeater, al introducir una secuencia estándar de path traversal, la aplicación devuelve un error porque el archivo no finaliza con la extensión requerida[cite: 7].
  5. Para superar esta restricción, se aplica la técnica de bypass por byte nulo modificando el parámetro con el payload: filename=../../../etc/passwd%00.png[cite: 7].
  6. Al enviar la solicitud modificada, el servidor responde con el código HTTP/2 200 OK, exponiendo íntegramente el contenido del archivo /etc/passwd[cite: 7].

Explicación del payload

El payload utilizado se compone de tres elementos: las secuencias de salto de directorio (../../../) para posicionarse en la raíz del sistema, el archivo objetivo (etc/passwd), y el byte nulo con la extensión requerida (%00.png)[cite: 7]. El byte nulo trunca la lectura en el backend de modo que el sistema operativo solo lee el archivo antes del carácter nulo, mientras que el filtro web valida la presencia de la extensión final requerida[cite: 7].

Mitigación recomendada

  • Actualización del entorno de desarrollo: Utilizar lenguajes de programación modernos y funciones nativas que no sufran de vulnerabilidades de truncamiento por bytes nulos[cite: 7].
  • Uso de funciones de mapeo seguro (Basename): Utilizar funciones integradas que extraigan únicamente el nombre base del archivo solicitado, descartando rutas relativas o caracteres especiales[cite: 7].
  • Validación mediante listas blancas (Whitelisting): Restringir los valores permitidos a un conjunto estricto de identificadores predefinidos, rechazando cadenas con caracteres nulos (%00) o barras[cite: 7].
