Laboratorio de Path Traversal

FILE PATH TRAVERSAL TRAVERSAL SEQUENCES BLOCKED WITH ABSOLUTE PATH BYPASS

Nivel: Apprentice | Tipo de explotación: PATH TRAVERSAL

Detalles del Reporte

Objetivo del laboratorio

El objetivo de este laboratorio es explotar una vulnerabilidad de path traversal en la visualización de imágenes de productos donde, a pesar de bloquear secuencias de escape comunes, la aplicación interpreta el archivo proporcionado en relación con un directorio de trabajo predeterminado; para resolverlo, debes evadir esta restricción lógica y lograr extraer con éxito el contenido del archivo crítico del sistema operativo, /etc/passwd.

Explicación técnica de la vulnerabilidad

La vulnerabilidad radica en una deficiencia en el control de acceso y en la validación de entradas de la aplicación, la cual intenta mitigar el riesgo de path traversal bloqueando únicamente las secuencias relativas de navegación (como ../); sin embargo, al no restringir el uso de rutas absolutas, el sistema procesa el parámetro de entrada de forma literal desde la raíz del servidor-ignorando el directorio de trabajo predeterminado-, lo que permite a un atacante omitir los filtros implementados y acceder de manera ilegítima a recursos críticos del sistema operativo, tales como el archivo /etc/passwd.

Procedimiento paso a paso

  1. El proceso inicia con la apertura de la aplicación Burp Suite y el uso de su navegador integrado, el cual evita conflictos de configuración con certificados de seguridad.
  2. En la sección Proxy > Intercept, se verifica que la función de intercepción se encuentre activada (Intercept is on) para pausar y capturar de manera temporal las peticiones HTTP.
  3. Una vez capturada la solicitud HTTP objetivo, se hace clic derecho sobre ella para desplegar el menú contextual y se selecciona la opción Send to Repeater.
  4. Dentro de la herramienta Repeater, en la solicitud GET /image?filename=, se reemplaza el nombre del archivo de imagen original por la ruta absoluta /etc/passwd.
  5. Al enviar la solicitud modificada, se observa que el servidor la procesa correctamente y devuelve una respuesta con el código de estado HTTP/2 200 OK, exponiendo el contenido íntegro del archivo solicitado.

Explicación del payload

El payload utilizado en este laboratorio consiste en una ruta absoluta directa, específicamente /etc/passwd, la cual se introduce en el parámetro afectado sin incluir ninguna secuencia de navegación relativa (../). Esta estructura elude el filtro de la aplicación permitiendo que la función de lectura de archivos del servidor interprete la entrada desde la raíz del sistema de archivos.

Mitigación recomendada

  • Uso de funciones de mapeo seguro (Basename): Utilizar funciones integradas en el lenguaje de programación que extraigan únicamente el nombre del archivo solicitado.
  • Validación mediante listas blancas (Whitelisting): Restringir los valores permitidos en los parámetros de entrada a un conjunto estricto de nombres de archivos válidos o identificadores predefinidos.
  • Directorio raíz confinado (Chroot o aislamiento): Asegurarse de que la aplicación web se ejecute con privilegios mínimos y que el acceso a los archivos esté estrictamente limitado a un directorio específico del sistema de archivos.
